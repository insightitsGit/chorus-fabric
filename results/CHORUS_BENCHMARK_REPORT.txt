SECTION 1: WHAT IS CHORUS
=============================================================

CHORUS (Coherent Hyperdimensional Orchestration for Unified Signal Streaming)
is a novel AI machine-to-machine (M2M) communication protocol that bypasses
text tokenization entirely. Instead of serializing language to text tokens and
making HTTP/REST API calls, CHORUS streams raw high-dimensional float32 tensor
vectors directly over bidirectional gRPC streams.

Core innovation:
  - AI models communicate in embedding space, not token space
  - Tensor Multiplication Cipher secures payloads: V_enc = V_raw @ K
  - Rolling SHA-256 Neural Watermark authenticates every chunk
  - Mode A (Orthogonal Isolation): two AI signals share one channel without crosstalk
  - Mode B (Holographic Superposition): two AI signals blend into one collective vector
  - Relay Node amplifies ciphertexts without ever decrypting them
  - Option B Control Plane issues ephemeral session keys with TTL

No existing protocol (gRPC, HTTP/2, MQTT, WebSocket) provides these primitives.

SECTION 3: NETWORK TOPOLOGY
=============================================================

  [Benchmark Client]         [Relay Node]              [Target Pod]
   eastus (Virginia)          eastus (Virginia)          germanywestcentral (Frankfurt)
   IP: dynamic                IP: 20.237.21.245          IP: 98.67.201.195
         |                         |                           |
         |---- gRPC stream ------->|                           |
         |   (US-internal, ~1ms)   |---- gRPC stream --------->|
         |                         |   (transatlantic, ~165ms) |
         |                         |<---- ack stream ----------|
         |<---- relay ack ---------|                           |
         |                                                     |
         |---- Control Plane handshake (Germany, :50051) ----->|

Signal path per chunk:
  1. Benchmark registers with Control Plane -> receives K, K_inv, watermark_seed
  2. Benchmark generates tensor V_raw from concept seed
  3. Watermark injected : V_wm = V_raw + alpha * watermark_vector(SHA-256(seed||seq))
  4. Encrypted          : V_enc = V_wm @ K  (float64 math, stored as float32)
  5. Sent to Relay (US) : V_enc as 512-byte gRPC payload
  6. Relay amplifies    : V_amp = scalar * V_enc  (safe on ciphertext)
  7. Relay logs SHA-256 fingerprint and forwards to Target (Germany)
  8. Target decrypts    : V_dec = V_amp @ K_inv
  9. Watermark verified : cosine_sim(V_dec, expected) >= 0.95
 10. Mode dispatch      : Isolation (W_A/W_B projection) or Superposition (add)
 11. Ack returned via Relay to Benchmark Client

SECTION 5: CRYPTOGRAPHIC PROPERTIES DEMONSTRATED
=============================================================

1. TENSOR MULTIPLICATION CIPHER
   K and K_inv generated via QR decomposition (float64 for stability)
   Encrypt: V_enc = V_raw @ K
   Decrypt: V_dec = V_enc @ K_inv
   Identity error in unit test: 1.86e-15  (machine epsilon, provably correct)
   Keys: ephemeral per-session, issued by Control Plane with 7200s TTL

2. ROLLING NEURAL WATERMARK
   seed = SHA-256(session_id || seq_num) -> seeded PRNG -> unit vector
   Verification: cosine_similarity(decrypted, expected) >= 0.95
   Prevents: replay attacks (seq_num bound), injection (unknown seed)
   Live result: 100% pass across 7766 transatlantic chunks

3. ORTHOGONAL ISOLATION (MODE A)
   W_A, W_B from QR decomposition: W_A @ W_B.T ~ 0
   Two AI signals share one channel; each recovers only its own
   Crosstalk in unit test: 0.000006%
   Recovery cosine_similarity: 1.0 (perfect reconstruction)

4. HOLOGRAPHIC SUPERPOSITION (MODE B)
   V_collective = V_A + V_B
   Both signals coexist in the same vector space
   Recovery cosine_similarity to each original: ~0.70

5. RELAY CONFIDENTIALITY
   Relay: V_amp = scalar * V_enc  (linear, safe on ciphertext)
   Relay logs SHA-256(V_enc) fingerprint only - never plaintext
   Relay never holds K_inv -> cannot decrypt payload
   Proved end-to-end across transatlantic 3-hop topology

SECTION 9: HOW TO REPRODUCE
=============================================================

Prerequisites:
  - Azure CLI  (az login, subscription set)
  - Docker Desktop running
  - Python 3.11+, PyTorch CPU, grpcio

Step 1 - Register ACI provider (one-time):
  az provider register --namespace Microsoft.ContainerInstance --wait

Step 2 - Deploy all 4 containers:
  cd C:/code/CHORUS
  ./azure_deploy.ps1 -ResourcePrefix chorus

Step 3 - Stream benchmark logs:
  $env:PYTHONUTF8 = "1"
  az container logs --resource-group chorus-rg-us --name chorus-benchmark

Step 4 - Download results after benchmark completes:
  ./azure_get_results.ps1

Step 5 - Analyze:
  python analyze_results.py --db chorus_results/chorus_benchmark.db

Step 6 - Destroy infrastructure (stop billing):
  ./azure_deploy.ps1 -Destroy
